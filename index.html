Write-up

Design rationale

Why a map. Our question starts with "where," so geography is the main encoding: position on the map is location on Earth. We used the Equal Earth projection because it keeps areas true. In our exploratory matplotlib maps (plain lat/lon grid) the Arctic looked far bigger than it is, which made polar warming look more widespread than it really is.

Why color = change, not temperature. Our baseline map (exploratory graph 3) showed that absolute temperature is dominated by the equator-to-pole gradient, which hides any change. So each square is colored by how far it moved from its own 1850–1900 average. We used a diverging red/blue scale centered on 0 because the sign matters (warmer vs cooler). The scale runs from −5 to +15 °C instead of being symmetric, because no square cools much more than 3 °C while some warm by almost 20 °C. A symmetric scale would have used half the colors on values that never appear. Values above 15 are clamped and the legend says "15+".

Why 5° squares. The model's native grid is about 1°, which gives 55,000 cells. That is slow to redraw in SVG and finer than a single model can be trusted. At 5° (2,592 squares) the patterns we care about are still clear: the Arctic, land vs ocean, and the North Atlantic "warming hole" south of Greenland.

Interactions.

  • Year slider and Play: the story is change over time, and a static map can only show one moment. Playing 1850 → 2100 shows warming staying small and patchy for a century and then spreading from the poles.
  • Scenario toggle (switching the displayed measure): the map stays in place and only the colors change, so you can compare the same place under both paths without moving your eyes between two maps.
  • Tooltip with a mini line chart (details on demand): color alone can't give an exact number or a whole history. Hovering shows the exact change and that square's full 1850–2100 history under both paths.
  • Linked global chart: shows where the current year falls on the global curve and how far apart the two paths are. Clicking or dragging on it sets the year, so it doubles as a second time control.

Alternatives we considered. (1) Small multiples, one map per decade per scenario: with 2 paths × 25 decades each map would be too small to read. (2) Two maps side by side, one per scenario: this halves the map size, and the toggle does the same job. (3) An animated latitude line chart (like graph 6): it clearly shows polar amplification but averages away longitude, so the warming hole disappears. We kept that as an exploratory graph.

Data transformations

  • Source: CMIP6 monthly near-surface air temperature (tas) from one model, NCAR CESM2, run r4i1p1f1, read from the public Google Cloud zarr stores with xarray (same method as the course notebook).
  • Monthly values → yearly averages (mean of the 12 months), converted from Kelvin to °C.
  • The ~1° grid is averaged into 5° squares, weighting each original cell by cos(latitude) so smaller high-latitude cells count less.
  • Each square's 1850–1900 average is subtracted from every year to get the change.
  • The historical run (1850–2014) is joined to the start of each scenario (2015–2100).
  • Global averages are computed on the original grid with cos(latitude) weights. Values are rounded to 0.1 °C.
  • Caveats: this is a single model and a single run, so the year-to-year wiggles are natural variability inside the model, not errors. CESM2 is known to warm more than most CMIP6 models, so the high-emissions numbers sit at the upper end of projections.

Code: scripts/prepare_data.py (download + processing) and scripts/exploratory.py (exploratory graphs).
