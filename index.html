Write-up

Motivation

Our first exploratory graph was the standard one, global average temperature as a single line. In CESM2 that line is a little over 1 °C above the 1850-1900 average by 2014, and by 2100 it reaches 2.4 °C on the low-emissions path and 6.4 °C on the high one. The line doesn't tell you where any of that happens, though. When we mapped the high-emissions run (exploratory graph 5), the warming was very uneven. Parts of the Arctic warm by more than 15 °C while a patch of the North Atlantic barely warms at all. We built the page around that, so you can see which places warm fastest and how much the emissions path changes it.

Design rationale

The question is about "where," so the map is the main view. A square's position is its location on Earth, and its color is how much that place has warmed. We went with the Equal Earth projection because it keeps areas accurate. Our exploratory matplotlib maps used a plain lat/lon grid, and the Arctic looked much bigger on those than it really is, which made polar warming seem to cover more of the planet than it does.

Color shows change from a baseline instead of the temperature itself. The baseline map (exploratory graph 3) plots raw temperature, and all you see is a warm equator and cold poles. A few degrees of change gets lost in that. So we compare each square to its own 1850-1900 average. For the palette we used D3's red/blue diverging scale (RdBu, flipped so red is warmer) centered on 0, since a square can go either way and warmer and cooler should look like opposites. The scale isn't symmetric. It runs from -5 to +15 °C because cooling is rare and small in this data (fewer than 0.1% of square-years fall below -3 °C), while some squares warm by almost 20 °C under high emissions. A symmetric scale would have spent half its colors on values that barely show up. Anything past either end gets the end color, and the legend labels the top "15+".

The model's own grid is about 1°, which is roughly 55,000 cells. That many SVG shapes redraw slowly, and it's more detail than one model run can support anyway. At 5° there are 2,592 squares, and the patterns we cared about still show up: the Arctic warming fastest, land warming faster than ocean, and the "warming hole" in the North Atlantic south of Greenland.

For the interactions we started with time. A static map can only show one year and our story is about change, so there's a year slider and a Play button. If you play it from 1850, the warming stays small and patchy for about a century and then spreads out from the poles.

The scenario buttons change the colors and leave the map where it is, so you can watch one place while you flip between the two emissions paths. With two separate maps you'd be looking back and forth. Hovering is for what color can't give you, which is an exact number and a history: you get the square's change for the current year and a small line chart of that square from 1850 to 2100 under both paths. Below the map, the global chart plots the average for both paths and marks the current year, so you can see how far apart the paths are at that point. You can also click or drag on it to set the year, which makes it a second time control.

We thought about three other designs. The first was small multiples, one map per decade for each scenario, but that's 50 maps and each one would be too small to read. Two maps side by side would cut each map to half the width, and the toggle already covers that comparison. The last idea was an animated chart of warming by latitude, like exploratory graph 6. It shows polar amplification clearly, but it averages over longitude, so the warming hole disappears. We left that one as an exploratory graph.

Data transformations

Everything comes from one model, NCAR's CESM2 (run r4i1p1f1), and one variable, monthly near-surface air temperature (tas). We read it from the public Google Cloud zarr stores with xarray, the same way the course notebook does. The processing steps, in order:

  1. Averaged the 12 months of each year into one yearly value and converted Kelvin to °C.
  2. Combined the ~1° grid cells into 5° squares with a weighted average, using cos(latitude) as the weight because cells near the poles cover less area.
  3. Subtracted each square's 1850-1900 average from every year to get the change.
  4. Joined the historical run (1850 to 2014) to the start of each scenario (2015 to 2100).
  5. Computed the global averages on the original grid, also weighted by cos(latitude).

Square values are rounded to 0.1 °C. This is a single run of a single model, so the year-to-year wiggles are the model's own natural variability. They aren't errors. CESM2 also runs warmer than most CMIP6 models, so its high-emissions numbers sit near the top of the projected range. The processing code is in scripts/prepare_data.py and the exploratory graphs are in scripts/exploratory.py.

Development process

Ryan Namdar built the D3 page, which covers the map, the color scale and legend, the hover tooltip with its mini chart, the Play button and slider, the scenario toggle, and the linked global chart. Austin Flippo wrote the data pipeline (scripts/prepare_data.py). It loads CESM2 from Google Cloud, builds the yearly 5° grids and baselines, and writes out data/temps.json for the page. David Li made the six exploratory graphs (scripts/exploratory.py) and the checkpoint video, and wrote the first draft of this write-up.

In total we spent about 15 people-hours, roughly 5 each, and most of that went into the data. We needed the same CESM2 run (r4i1p1f1) for the historical period and both scenarios. Finding matching runs in the Google Cloud CMIP6 catalog and then getting the zarr stores to load with xarray was slow going. The other big piece was processing, especially getting the JSON small enough to load quickly in a browser. We store each value as a whole number of tenths of a degree, which keeps the file at about 2.4 MB. Once the data was clean, the D3 side went faster.
